WHAT ./run.sh DOES
------------------

1. Finds Nix and enters the flake development shell.
2. Runs scripts/run-mirage-demo.sh.
3. Uses an isolated opam root at:

       /tmp/flaketest-mirage-opam-root

4. Creates/uses the opam switch "mirage-4.10" with OCaml 4.14.2.
5. Installs Mirage >= 4.9.0 and < 4.12.0.
6. Selects target "macosx" on Darwin and "unix" elsewhere, unless
   MIRAGE_TARGET overrides it.
7. Runs mirage configure, make depend, and make build.
8. Executes mirageapp/dist/hello.

The program logs "hello from MirageOS on Nix" four times, one second apart.

MIRAGE ARCHITECTURE CONCLUSION
------------------------------

Older MirageOS code exposed a highly functorized architecture: applications
were commonly OCaml functors receiving implementations of network, console,
storage, and other signatures. Functoria generated main.ml and applied those
functors according to the typed graph in config.ml.

That architecture was softened, not removed:

- Current Mirage still exposes the Functoria DSL and typed implementation graph.
- Applications with injected stacks/storage/devices can still be functors.
- Simple jobs with no explicit injected devices can use "let start ()".
- Some abstractions were made concrete, such as Lwt.t and Cstruct.t.
- MirageOS 4 moved much backend construction into Dune cross-compilation
  contexts, opam-monorepo, target runtimes, and target-specific libraries.

This application is the simple no-argument case:

    config.ml:     main "Unikernel" job
    unikernel.ml:  let start () = ...
